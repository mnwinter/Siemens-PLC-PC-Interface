RUNGPROOF CORRECTED-CANDIDATE DELTA RETEST
==========================================

Purpose: qualify corrected candidate 0.2.0-pilot.2 against the accepted
0.2.0-pilot.1 baseline without rewriting or pretending the baseline covered a
different EXE.

Safety boundary
---------------

- Use only the isolated bench PLC with no physical field I/O or machine energy.
- Keep the accepted baseline evidence folder unchanged.
- If Simulation_Enable must be forced because no system-start rung exists,
  document that fact and remove the force after testing.

1. Prepare the corrected candidate
----------------------------------

Extract the corrected ZIP to a new folder on the PLC-reachable VM. In
PowerShell, change to that folder and run:

  .\BENCH-PREFLIGHT.ps1 `
    -BaselineEvidenceDirectory "C:\path\to\accepted-baseline\bench-evidence"

Expected:

- package integrity PASS;
- PLC_CONNECTION_ATTEMPTED: FALSE;
- BENCH-DELTA-RESULT.json created under this package's bench-evidence folder.

2. Establish healthy operation
------------------------------

- Open the ten-tag DB14 watch table in TIA.
- Start RungProof and explicitly authorize Connect Real PLC.
- Confirm heartbeat echo, Simulation_Comm_OK TRUE, Simulation_Timeout FALSE.
- Press Run and observe one complete conveyor/pusher cycle.
- Reconfirm RungProof writes only DB14.DBX0.0, DB14.DBX0.1, DB14.DBX0.2,
  and DB14.DBD2.

3. Explicit Disconnect
----------------------

While connected telemetry is visible, select PLC > Disconnect.

RungProof must immediately show:

- CLOSING and then REAL PLC DISCONNECTED;
- Health CLOSING/DISCONNECTED, never HEALTHY;
- Heartbeat, Echo, Enable, Comm OK, and Timeout unavailable (`--`);
- PLC-owned conveyor_running and pusher_extend unavailable (`--`).

After the watchdog delay, TIA must show:

- Simulation_Comm_OK FALSE;
- Simulation_Timeout TRUE;
- Conveyor_Run FALSE;
- Pusher_Extend FALSE.

4. Reconnect and fresh Run
-------------------------

- Reconnect explicitly.
- Confirm live telemetry returns only after a real connected exchange.
- Confirm the simulation does not resume by itself.
- Press Run and confirm a fresh cycle starts.

5. Network loss and automatic recovery
--------------------------------------

While connected, disable the VM network adapter long enough to exceed the
watchdog timeout.

- RungProof must show RECONNECTING and unavailable PLC telemetry (`--`).
- The RungProof plant must stop applying PLC command samples. The retained
  baseline already proves the PLC watchdog safe state for this exact target;
  do not claim a simultaneous TIA observation if disabling the VM adapter also
  disconnects TIA.
- Re-enable the adapter.
- RungProof must reconnect automatically, but motion must remain stopped.
- Press Run and confirm a fresh cycle starts.

6. Close behavior
-----------------

Close RungProof while connected. After the watchdog delay, confirm in TIA that
Simulation_Comm_OK is FALSE, Simulation_Timeout is TRUE, and both PLC commands
are FALSE.

7. Record and validate
----------------------

Set every observation in bench-evidence\BENCH-DELTA-RESULT.json to true only
when directly observed. Fill approval.result with PASS, approvedBy, approvedAt,
and notes. Then run:

  .\VALIDATE-BENCH-DELTA.ps1 `
    -BaselineEvidenceDirectory "C:\path\to\accepted-baseline\bench-evidence"

Expected: RUNGPROOF_BENCH_DELTA_ACCEPTANCE: PASS.

Return these current-candidate files:

- BENCH-PREFLIGHT.json
- BENCH-DELTA-RESULT.json
- BENCH-DELTA-ACCEPTANCE.json
- screenshots showing disconnected/reconnecting `--` telemetry and the
  corresponding TIA safe-state values.
